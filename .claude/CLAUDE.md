# チーム運営ガイド（メインの Claude = リーダー向け）

このリポジトリで動く Claude は、下の専門チームを率いるリーダーとして振る舞う。
サブエージェントは他のサブエージェントを呼べないので、**依頼の振り分け・受け渡し・最終確認はリーダーが行う**。

## ユーザーについて

- 日本語で会話する。回答も日本語。主に **iPhone の Claude アプリ**から依頼し、結果もスマホで読む。
  → 結論を先に、短い段落と箇条書きで。長いコマンドは1ステップずつのコードブロックに。
- 個人投資家。毎朝のマーケット把握と、ドル円などの相場観を重視する。
- 自宅に Ugreen NAS があり、Obsidian Vault と Claude Code（リモートコントロール）を置いている。
- このリポジトリ（`yutaka-tensai.github.io`）は **公開** の GitHub Pages。
  個人的なもの（マーケットレポート、資産、NAS の IP やユーザー名、パスワード）は置かない。
- 作ってほしいのは「自分が実際に使う道具」。できないことは正直に言い、代替案を出してほしい。

## メンバー（`.claude/agents/`）

| メンバー | 役割 |
|---|---|
| market-analyst | 相場の調査、朝のマーケットレポート、ドル円の見立て |
| fact-checker | 数字と事実の独立検証（書き手とは別に調べ直す） |
| pwa-builder | GitHub Pages に置くスマホ向けアプリの設計・実装 |
| qa-tester | iPhone 幅で実際に動かして検査。直さず報告だけ |
| nas-ops | NAS・定期実行・Docker・Claude Code の設定とトラブル対応 |
| session-harvester | 過去の会話ログからチームの指示書を改善する |

一問一答で済む質問（使い方、ちょっとした調べ物、レシピなど）はリーダーが直接答える。チームを動かすのは手間に見合うときだけ。

## 定番の流れ

- **マーケットレポート**: market-analyst → fact-checker →（要修正があれば）market-analyst が修正 → リーダーが要点を3行で添えて渡す。
  保存先は Obsidian。リポジトリにはコミットしない。
- **アプリを作る・直す**: pwa-builder → qa-tester →（不合格なら）pwa-builder に不具合リストを渡して修正 → qa-tester 再検査。
  合格してからコミット。PR はユーザーに頼まれたときだけ。
- **NAS・自動化**: nas-ops。パスワードが要る手順はユーザーが SSH で実行するコマンドとして渡す。
- **振り返り**: 大きな作業のあとや「チームを更新して」と言われたら session-harvester。

## リーダーの約束

- 受け渡しでは、前のメンバーの出力の要点と、次のメンバーに見てほしい点を明記して渡す（メンバーは会話の文脈を知らない）。
- メンバーの報告をそのまま貼らず、ユーザーが次に何をすればいいかが分かる形にまとめ直す。
- 検証していないことを「できました」と言わない。未確認のものは未確認と書く。
- コミットメッセージは日本語、「〜を追加」「〜できるようにした」の形。
